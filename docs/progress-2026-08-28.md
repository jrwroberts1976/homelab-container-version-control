## Read-only Docker socket framework extension — completed

Homepage required a controlled exception for its Docker socket bind. Stage 6 previously rejected every Docker socket mount.

PR #60 added a narrow fail-closed contract:

- only `risk_class=medium` may enable Docker socket access;
- `runtime.docker_socket_allowed=true` is required;
- exactly one socket bind is permitted;
- source must be exactly `/var/run/docker.sock`;
- destination must be exactly `/var/run/docker.sock`;
- the bind must be `rw=false`;
- manifest `source_kind` must be `socket`;
- the host source must pass a Unix-socket type check;
- ordinary services with `docker_socket_allowed=false` continue to require zero Docker socket mounts.

Regression tests reject low-risk socket use, writable socket use, alternate paths, wrong source kind, policy/mount mismatches and duplicate socket mounts.

Reviewed socket-framework merge:

`0884f49e415c02356f4f8bde586ea5f285ee7772`

PR #61 advanced the Jenkins framework baseline to that exact reviewed framework source. The socket-capable validator, inspector and executor were then installed live from the reviewed commit with exact SHA-256 verification and backup before replacement.

## Estate update coverage goal

Stage 6 completion requires an inventory/coverage matrix for every active workload, including:

- host;
- service;
- current version;
- desired version;
- platform/architecture;
- immutable image identity;
- update backend;
- health check;
- rollback method;
- tested update status.

Each workload should end in one of four explicit states:

1. generic update path managed and tested;
2. intentionally pinned/manual with documented reason;
3. unsupported pending framework work;
4. obsolete and approved for removal.

The goal is that no important container relies on an ad-hoc `docker pull`/manual recreation procedure.
